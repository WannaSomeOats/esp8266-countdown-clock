# 双层 ESP8266 倒数日 — 2 键交互设计

> 硬件前提：1.8" ST7735（128×160）+ 2 个按键（A 左 / B 右）
> 页面：倒数日主页 / 番茄钟 / 日历 / 天气 / 设置

---

## 一、核心矛盾与解法

只有 2 个键，却有 5 个页面 + 每页内部还要选值 —— 冲突点在于：

> **短按到底用来"翻页"，还是用来"选值"？**

解法是把交互分成**两层状态**，并把**长按的语义全局固定**：

| 状态 | 短按的含义 | 进入 / 退出方式 |
| --- | --- | --- |
| **① 浏览态**（默认） | 上一页 / 下一页 | 长按 B 进入操作态 |
| **② 操作态**（页内） | 上一项 / 下一项（加减值） | 长按 A 退回浏览态 |

因为"长按"的含义永远不变，用户只需记住一句话：

> **左退右进 · 短按选，长按走**

---

## 二、四条全局铁律

| 手势 | 含义 | 说明 |
| --- | --- | --- |
| **A 短按** | 上一个 / 减一 | 浏览态翻页；操作态选上一项 |
| **B 短按** | 下一个 / 加一 | 浏览态翻页；操作态选下一项 |
| **A 长按**（≥0.8s） | **返回上一级** | 操作态→浏览态；任何页→主页 |
| **B 长按**（≥0.8s） | **确认 / 进入** | 浏览态→操作态；操作态→确认/深入 |

- 阈值建议：**短按 < 0.8s，长按 ≥ 0.8s**，长按触发后松手不再触发短按事件。
- **不用双击**：小屏设备上双击误触发率高，收益低。真要加，只留给冷门功能（如双击 A 熄屏）。

## 三、页面环（浏览态）

五页循环，**默认停在倒数日主页**：

```
倒数日 ──► 番茄钟 ──► 日历 ──► 天气 ──► 设置 ──┐
  ▲                                            │
  └────────────────────────────────────────────┘
```

- A 短按 = 上一页，B 短按 = 下一页，两端循环。
- **30 秒无操作**：自动回主页。
- **60 秒无操作**：背光熄灭（BLK 拉低），任意键唤醒并直接执行该键的浏览态动作（不吞键）。

---

## 四、两态状态机

### 浏览态

| 按键 | 行为 |
| --- | --- |
| A 短按 | 上一页 |
| B 短按 | 下一页 |
| **B 长按** | 进入当前页的操作态 |
| A 长按 | 回主页（若已在主页，见第六节例外 2） |

### 操作态

| 按键 | 行为 |
| --- | --- |
| A 短按 | 上一项 / 减一 |
| B 短按 | 下一项 / 加一 |
| **B 长按** | 确认（保存并返回浏览态，或进入下一级子项） |
| A 长按 | 取消 / 退回上一层（进入编辑前的值不保存） |

> 进入操作态时，界面要给一条**明显的视觉提示**：标题栏变反色，或屏幕顶/底出现一条高亮条。用户必须一眼知道"我现在是在翻页还是在选值"。

## 五、各页面的操作态内容

| 页面 | 浏览态显示 | 长按 B 进入后能做什么 |
| --- | --- | --- |
| **倒数日** | 大字「距 XX 还有 12 天 5 时」+ 底行「室内 24.5℃ / 58%」 | 快捷修改目标日期（年 → 月 → 日 逐级） |
| **番茄钟** | 大字「25:00」+ 4 个轮次点 | 菜单：开始 / 暂停 / 重置 / 设置专注与休息时长 |
| **日历** | 当月月视图，今日高亮，目标日带标记 | 翻月 → 再深入：翻年 / 跳到今天 / **设为倒数目标日** |
| **天气** | 今明后 3 天：图标 + 高低温 | 手动刷新 / 切换城市 |
| **设置** | 参数列表（高亮当前项） | 逐项进入编辑 |

### 设置页的完整条目建议

1. 目标日期
2. 目标名称（如"春节""生日"）
3. 屏幕亮度
4. 背光超时时间
5. 蜂鸣器开关 / 音量
6. 番茄专注时长 / 休息时长
7. 天气城市
8. 自动刷新间隔
9. 手动授时
10. WiFi 设置
11. 恢复出厂

> 长按 A 逐级退回：编辑值 → 条目列表 → 浏览态。

## 六、三条例外规则

1. **番茄钟计时中的特殊映射**
   当计时正在运行、且当前停留在番茄钟页时：
   - **B 短按 = 暂停 / 继续**（最高频操作，一键直达，不必进菜单）
   - **B 长按 = 结束并重置**
   - A 短按 = 照常翻页（离开番茄钟页不影响后台计时）

2. **主页 A 长按 = 立即刷新**
   在主页时"返回上一级"没有意义，这一格空闲，复用为**立刻触发一次授时 + 天气刷新**，并在屏幕上给个"刷新中"转圈反馈。

3. **自动回主页 + 熄屏**
   30s 无操作回主页，60s 无操作熄背光。任何按键唤醒时**不吞键**，直接执行该键在当前页的行为。

## 七、组合键（逃生舱，日常不用）

| 组合 | 作用 |
| --- | --- |
| **A + B 长按 3 秒** | 进入 WiFi 配网（AP 模式，手机连接后填 SSID/密码） |
| 上电时**按住 A** | 恢复出厂设置（清 WiFi、清目标日期） |
| 上电时**按住 B** | 强制重新授时 + 抓取天气 |
| 上电时**同时按住 A + B** | 进入"开机自检"页：显示 I2C 扫描结果、RTC 状态、内存余量 |

## 八、三个典型场景的完整按键流程

### 场景 1：把倒数目标改成 2027-02-06

```
主页（浏览态）
 └ B 长按        → 进入倒数日操作态，光标停在"年"
   └ A/B 短按    → 调年 → 2027
     └ B 长按    → 确认，光标跳到"月"
       └ A/B 短按 → 调月 → 2
         └ B 长按 → 确认，光标跳到"日"
           └ A/B 短按 → 调日 → 6
             └ B 长按 → 保存并写入 RTC，回到浏览态
共 5 次长按 + 若干短按。任一环节 A 长按 = 逐级取消。
```

### 场景 2：开始一个 25 分钟番茄钟

```
番茄钟页（浏览态）
 └ B 长按        → 菜单，光标停在"开始"
   └ B 长按      → 立即开始计时
（计时中）
 └ B 短按        → 暂停
 └ B 短按        → 继续
 └ B 长按        → 结束并重置
```

### 场景 3：看下个月日历，把 15 号设为目标日

```
日历页（浏览态）
 └ B 长按        → 进入日历操作态，光标在"月"
   └ B 短按      → 下个月
     └ B 长按    → 进入日子选择
       └ A/B 短按 → 移动到 15 号
         └ B 长按 → 确认 → 弹出"设为倒数目标日？"
           └ B 长按 → 确认写入，A 长按 → 取消
```

## 九、优化建议：为什么值得加第 3 个键

**2 键方案完全可行，但代价是"长按"被高频使用**，而长按有两个天然问题：

- 触发时间长（0.8s），连续操作时手感偏慢
- 误判风险 —— 用户以为短按、实际触发长按时，会跳出预期界面

**3 键方案（↑ / ↓ / 确认）可以把"长按"从高频路径里彻底移除**：
翻页/选值全用短按，"确认"用一个独立键，误操作率大幅下降。

而且你的引脚够用 —— 前面确认过：**GPIO12（D6）零约束可放心用，A0 也完全空闲**。所以：

| 方案 | 按键 | 引脚代价 | 建议 |
| --- | --- | --- | --- |
| 双臂按键 | A / B / 确认 | GPIO2 + GPIO12 + A0 | 推荐 |
| **EC11 旋转编码器** | 旋转 + 按下 | GPIO2 + GPIO12 + A0 | **最推荐** |
| 双键 | A / B | GPIO2 + GPIO12 | 可行，需学习成本 |

倒数日这类要"调日期、选城市、调亮度"的设备，**EC11 编码器体验是质变** —— 旋转调数比连点按钮快一个数量级，而且只占 3 个脚，和 3 按键一样。

> 结论：2 键方案可以落地（本文档就是完整可行的），但你有引脚余量，加一个确认键或直接上编码器，是性价比最高的一步改进。

## 十、2 个 GPIO 的互动方式全集

"只有 2 个 GPIO"看起来是死约束，实际有**四条完全不同的路线**，其中两条根本不用新增引脚。

### 路线 1 · 不改硬件，深挖手势（2 个按键）

| 手势 | 触发条件 | 典型用途 | 代价 |
| --- | --- | --- | --- |
| 短按 | < 0.8s | 上一个 / 下一个 | — |
| 长按 | ≥ 0.8s | 确认 / 返回 | — |
| **长按自动重复** | 长按 0.5s 后开始每 0.3s 步进，1.5s 后提速到 0.1s | 调日期、调亮度，避免连点 60 次 | **必须做**，否则调数值极其痛苦 |
| **双击** | 两次短按间隔 < 300ms | 双击 A = 一键回主页；双击 B = 确认并保存 | 误触率上升 |
| 三击 | 三次短按 | 冷门开关（如蜂鸣器总开关） | 不建议，用户记不住 |
| A + B 同时按 | 两键都按下 | WiFi 配网 / 恢复出厂 | 需要同时按，手感一般 |
| **长按预览 · 松手确认** | 按住 A 时连续自动翻页，松手停下 | 快速浏览月份 / 城市列表 | 需要明确的视觉反馈 |
| 上电时按住 | 上电瞬间 | A = 恢复出厂，B = 强制授时+抓天气 | — |

> 其中**长按自动重复**是刚需。没有它，把年份从 2026 调到 2030 要按 4 次还好，但调到目标月的"日"要连点几十次，体验会崩。

### 路线 2 · 修饰键模型（2 个按键，功能直接翻倍）★ 最被低估

把 A 键当成键盘上的 **Shift**：

- 单独按 B = 正常动作
- **按住 A 不放 + 按 B = B 的第二套功能**

举例：

| 操作 | 正常功能 | 按住 A 时的功能 |
| --- | --- | --- |
| B 短按 | 下一页 | 直接跳到设置页 |
| B 长按 | 进入当前页操作态 | 进入"快捷菜单"（亮度/静音） |
| A 短按 | 上一页 | — |

**成本为零**：不需要第 3 个按键、不需要改硬件，只是在代码里多一个状态位。
唯一要求：界面左上角常驻一句提示「按住 A —」，让用户知道还有第二层。

### 路线 3 · 换输入器件（还是 2 个 GPIO）

| 器件 | 占 GPIO | 说明 |
| --- | --- | --- |
| 2 个轻触按键 | 2 | 当前方案，最便宜、最通用 |
| **EC11 旋转编码器** | 2（A / B 两相） | ★ 旋转无级调值 + 无级翻列表，是 2 GPIO 能实现的最强交互。缺点：EC11 还有个"按下"脚，要用需另占 A0 |
| 2 个电容触摸焊盘 | 2 | 面板贴铜箔，无机械寿命问题。**注意：ESP8266 没有原生触摸外设**（那是 ESP32 的 T0~T9），只能用软件 RC 充放电时间测量近似实现，稳定性一般；稳妥做法是用 TTP223 之类的触摸模块，1 个 GPIO 对应 1 个触摸键 —— 引脚数和机械按键一样，只是不磨损 |
| 1 按键 + 1 编码器 | 2 | 混合方案：按键负责"确认"，编码器负责"调节" |

### 路线 4 · 挂到 I2C 上，新增 GPIO = 0 ★★ 隐藏答案

你的 I2C 总线已经在跑 AHT30（0x38）+ PCF8563（0x51），还有大量空闲地址：

| 器件 | 占 GPIO | 说明 |
| --- | --- | --- |
| **PCF8574** | **0** | 挂在 I2C 上，一次多出 **8 个 IO**（地址 0x20~0x27）→ 想接几个键就接几个键 |
| I2C 旋转编码器模块 / **AS5600 磁角度传感器** | **0** | 直接得到一个"无级旋钮"，GPIO 一个都不占 |
| TTP224 四路触摸模块 | 0 或 1 | I2C 版直接 0 占用；数字输出版占 1 个 IO 却能读 4 个触摸键 |

**这是唯一能真正突破"2 个 GPIO"上限的路** —— 不占新引脚，全靠 I2C 扩容。

### 六种「按键分权范式」对比

同样 2 个按键，把权限分配方式换一下，就是完全不同的产品手感：

| 范式 | A 键 | B 键 | 适合 | 缺点 |
| --- | --- | --- | --- | --- |
| ① 对称加减（本文方案） | ﹣ / 上一个 | ＋ / 下一个 | 列表 + 数值调节 | 需要两态区分，有学习成本 |
| ② 模式 / 动作分权 | 只负责切页面 | 只负责执行当前页唯一动作 | 每页只有一个主操作的设备 | 页内条目多了就不够用 |
| ③ 修饰键模型 | 兼任 Shift | 双层含义 | 功能多、按键少 | 用户要记住组合 |
| ④ 主从（80 / 20） | 唯一主导键，承担 80% 操作 | 只做返回 | 用途极单一的设备（如纯倒数日） | 功能扩展性差 |
| ⑤ 长按预览 · 松手确认 | 连续浏览候选值 | 确认选择 | 日历、长列表 | 必须做视觉反馈 |
| ⑥ 摩尔斯编码 | 点（短按） | 划（长按） | 理论上能输入数字/字母 | 学习成本极高，**不推荐** |

### 无论选哪条路线，两条体验铁律

1. **长按必须有进度反馈**
   按住时在屏幕上画一个填充进度环（0.8s 走满）。用户看不到"还差多久触发"，就会一直按下去或者不敢按。

2. **必须防误触**
   手势越多，误触越多。触发长按 / 双击时给**蜂鸣器一声短响 + 屏幕闪一下**，是最低成本的保险。同时把长按阈值定在 0.8s（不低于 0.6s），能过滤掉绝大部分无意按压。

### 四条路线的取舍建议

| 你的优先级 | 选哪条 |
| --- | --- |
| 完全不改硬件，先把功能跑通 | 路线 1（手势）+ 路线 2（修饰键）组合 |
| 想要最好的调节手感 | 路线 3：EC11 旋转编码器 |
| 想留出最大的扩展空间（以后加更多键） | 路线 4：I2C 上挂 PCF8574 |
| 追求极致简单、就一个倒数功能 | 路线 1 + 范式 ④（主从模型） |

> 我个人最推荐的组合是：**路线 2（修饰键）+ 路线 1 的长按自动重复**。
> 这两个都不花一分钱、不加一个引脚，却能把 2 键的表达能力拉到接近 3 键的水平。
